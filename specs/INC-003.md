`build_sleep_layer` perform no I/O. No new dependency: standard-library `json` and DuckDB.

## 2. Inputs and failure contract

Sleep files are the manifest rows with `source = 'sleep'`
(`wearable_events/<folder>/sleep.json`). A participant without a sleep file is allowed.

`PipelineError` (CLI exit 1, before any table is touched) is added for: a sleep file that
cannot be read or is not valid UTF-8 JSON; a sleep file whose top level is not an array; an
array element that is not an object. All earlier failure conditions are unchanged.
Everything inside a session object (missing keys, wrong types, bad values) is a field-level
defect and never raises.

`build_sleep_layer` receives `files` as relative path -> parsed JSON array, in any order; it
sorts paths, so output is independent of mapping order.

## 3. Normalization

`parse_local_timestamp(raw)`: returns `None` unless `raw` is a `str`. Trim surrounding
whitespace, then accept only `YYYY-MM-DDTHH:MM:SS`, optionally followed by a fraction of
1 to 6 ASCII digits and optionally by `Z` or `+HH:MM` / `-HH:MM`, all ASCII, a real calendar
date and time (no leap second, offset hours 0 to 23, minutes 0 to 59). Anything else
(space separator, date only, basic format, comma fraction, `+HH`, non-ASCII digits) returns
`None`. A naive value is already UTC-05:00 local time and is returned unchanged. A value with
`Z` or an offset is converted to UTC and then to UTC-05:00. The result is a naive
`datetime` holding local time.

Session and stage typing rules (JSON values):

- `date`: a string, parsed by `parse_iso_date`; anything else is unparseable.
- `sleep_onset`, `sleep_end`, `start_time`, `end_time`: `parse_local_timestamp`.
- `efficiency_pct`: a JSON number (not a boolean, not a string) between 0 and 100 inclusive,
  else invalid. `restlessness`: a JSON number between 0 and 1 inclusive, else invalid.
- `stage`: a string, kept as given (trimmed text is not applied); known names are exactly
  `light`, `deep`, `rem`, `awake`. A non-string name is invalid and stored NULL.
- `duration_min`: a JSON integer (not a boolean, float or string) that is at least 1,
  else invalid.
- `stages`: a JSON array of objects. A missing or non-array `stages` value is a session
  with zero stages and flags `SLEEP_STAGE_INVALID`; a non-object element is one invalid
  stage with all fields NULL.
- Session participant id: the object's `participant_id` when it is a non-blank string, else
  the name of the participant folder in the path. A mismatch between the two is not
  checked.
- Missing keys are treated as invalid values of the field.

## 4. Silver

Withheld values are NULL; nothing is dropped; original text stays in the raw files and, for
flagged sessions, in `quality_rejects`. No raw-text or row-number column is stored.

### `silver_sleep_sessions`

Grain: one row per element of every sleep file. Natural key (`participant_id`,
`local_date`), unique when no row has `is_duplicate_key` and no `local_date` is NULL.
Rows are ordered by (path, array position) when written.

Columns: `participant_id` (VARCHAR), `local_date` (DATE), `sleep_onset`, `sleep_end`
(TIMESTAMP, local), `supplied_efficiency_pct`, `restlessness` (DOUBLE),
`is_duplicate_key`, `is_orphan`, `is_out_of_window` (BOOLEAN), `quality_flags` (VARCHAR).
`is_out_of_window` is true only for a parsed date outside the study window.
`quality_flags` is the comma-joined, alphabetically sorted rule ids that flagged the session
(including stage-level rules), or NULL.

### `silver_sleep_stages`

Grain: one row per element of each session's `stages` array. Key (`participant_id`,
`local_date`, `stage_index`) with `stage_index` the 1-based array position; unique under the
same condition as sessions. A session with no valid `stages` array has no stage rows.

Columns: `participant_id`, `local_date`, `stage_index` (INTEGER), `stage` (VARCHAR),
`start_time`, `end_time` (TIMESTAMP, local), `duration_min` (INTEGER, supplied value, NULL
when invalid), `derived_duration_min` (DOUBLE: (`end_time` - `start_time`) in minutes, NULL
unless both times parse), `quality_flags` (VARCHAR: stage-level rule ids that flagged this
stage, sorted, or NULL).

Orphan sessions, out-of-window sessions and sessions with an unparseable date have silver
rows but never reach gold.

## 5. Stage validity and metrics

A stage is **valid** when its name is known, its `duration_min` is valid, and both its
times parse. Only valid stages contribute to metrics, with their supplied `duration_min`.

`compute_sleep_metrics(stages)` takes `(name, duration)` pairs where `duration` is `None`
for an invalid duration or a stage whose times did not parse. A pair is valid when
`duration` is not `None` and `name` is known. Let `A` be the sum of valid non-awake
durations, `T` the sum of all valid durations, `D` the sum of valid `deep` durations.

- `total_sleep_min`: `None` when `stages` is empty or when any invalid stage has a name other
  than exactly `awake` (an unknown name counts as non-awake); otherwise `A`.
- Percentages are `None` when `stages` is empty, when any stage is invalid, or when
  `A == 0`.
- `deep_sleep_pct = D / A * 100`; `sleep_efficiency_pct = A / T * 100`. Plain floating-point
  division, not rounded.

When the layer calls `compute_sleep_metrics`, a stage whose name is missing or not a
string is passed with the name `""` (unknown, hence non-awake), and a non-object stage
element as `("", None)`. A stage whose duration is invalid, or whose `start_time` or
`end_time` does not parse, is passed with duration `None`; a `duration_min` of 0 is invalid
at session level (section 3), so it is passed as `None`, whereas `compute_sleep_metrics`
itself accepts a duration of 0.

Session spans use `sleep_end - sleep_onset` only for the S-02 rule; no metric uses them.

## 6. Quality rules

All sleep rules use source `sleep`. For every sleep rule `checked_count` is the number of
sessions read (zero when there are no sleep files) and `failed_count` is the number of
sessions flagged by the rule (a session counts once per rule even if several fields or
stages fail). Every rule always produces one `quality_results` row. One `quality_rejects`
row is written per flagged session and rule, with `row_ref`
`"{relative_path}:{array_position}"` (1-based) and `raw_values` the JSON of the raw session
object (all keys and the full `stages` array, nothing altered), `reason` equal to the rule's
reason text. Vocabulary is unchanged (handling `flag | withhold_field | exclude_from_output`,
severity `high | medium`). `quality_flags` and gold flags use the rule ids.

| rule_id | Session fails when | Handling | Severity | Reason (exact text) |
|---------|--------------------|----------|----------|---------------------|
| `SLEEP_ORPHAN_PARTICIPANT` | its participant id is not enrolled in `participants.csv` | `exclude_from_output` | `medium` | `sleep participant_id is not enrolled in participants.csv` |
| `SLEEP_DUPLICATE_PARTICIPANT_DAY` | (`participant_id`, parsed `date`) occurs in more than one session (NULL dates are not grouped) | `withhold_field` | `high` | `participant_id and date occur in more than one sleep session` |
| `SLEEP_DATE_UNPARSEABLE` | `date` is missing or not a valid `YYYY-MM-DD` calendar date | `exclude_from_output` | `medium` | `sleep date is not a valid YYYY-MM-DD calendar date` |
| `SLEEP_DATE_OUT_OF_WINDOW` | the date parses but is outside the study window | `exclude_from_output` | `medium` | `sleep date is outside the study window` |
| `SLEEP_SESSION_FIELD_INVALID` | `sleep_onset`, `sleep_end`, `efficiency_pct` or `restlessness` is missing or invalid (section 3) | `withhold_field` | `medium` | `sleep_onset, sleep_end, efficiency_pct or restlessness is missing or invalid` |
| `SLEEP_STAGE_INVALID` | `stages` is missing or not an array, or any stage has an unknown or non-string name, an invalid `duration_min`, or an unparseable `start_time` or `end_time` | `withhold_field` | `medium` | `a sleep stage has an unknown name, an invalid duration or an unparseable time` |
| `SLEEP_STAGE_DURATION_MISMATCH` (S-01) | any stage with a valid `duration_min` and both times parsed has (`end_time` - `start_time`) not equal to `duration_min` x 60 seconds | `flag` | `medium` | `a sleep stage duration differs from its timestamp interval` |
| `SLEEP_STAGE_GAP_OR_OVERLAP` | for any two consecutive stages (by array position) whose times parse, `start_time` of the later one is not equal to `end_time` of the earlier one | `flag` | `medium` | `consecutive sleep stages have a gap or overlap` |
| `SLEEP_SPAN_OUTLIER` (S-02) | `sleep_end` - `sleep_onset` is strictly more than 12 hours | `flag` | `medium` | `sleep session span is longer than 12 hours` |
| `SLEEP_FINAL_STAGE_MISALIGNED` (S-03) | the last stage's `start_time` and `sleep_end` both parse and differ | `flag` | `medium` | `final sleep stage does not start at sleep_end` |
| `SLEEP_EFFICIENCY_MISMATCH` (S-04) | `supplied_efficiency_pct` and the session's derived `sleep_efficiency_pct` are both non-NULL and differ by more than 1 point | `flag` | `medium` | `supplied efficiency_pct differs from the derived efficiency by more than 1 point` |
| `SLEEP_ONSET_NOT_MINUTE_ALIGNED` (S-05) | `sleep_onset` parses and has non-zero seconds or microseconds | `flag` | `medium` | `sleep_onset is not aligned to a whole minute` |

Notes:

- Sessions shorter than 3 hours get no rule. A final awake stage ending after `sleep_end`
  (S-07) is not a defect and gets no rule.
- The derived efficiency used by `SLEEP_EFFICIENCY_MISMATCH` is the session-level
  `compute_sleep_metrics` value (so it is NULL, and the rule cannot fire, when any stage is
  invalid or the stage list is empty).
- Stage-level rules (`SLEEP_STAGE_INVALID`, `SLEEP_STAGE_DURATION_MISMATCH`,
  `SLEEP_STAGE_GAP_OR_OVERLAP`) also appear in the `quality_flags` of the affected stage row
  (for gap or overlap, the later stage of the pair) and of the session.
- The rule table grows from 7 to 19 rows; the report table and `quality_results` list all of
  them ordered by `rule_id`, `source`.

## 7. `SleepLayer`

Frozen dataclass with these list fields, in deterministic order (sessions by (path,
array position), stages by session then `stage_index`): `sessions` (rows of
`silver_sleep_sessions`), `stages` (rows of `silver_sleep_stages`), `rejects`
(`(rule_id, relative_path, array_position, raw_session)` tuples), `failed`
(`Counter` rule id -> failed sessions), `checked` (number of sessions), and `daily`
(`dict[tuple[str, date], SleepDay]`, one entry per participant-day with at least one
contributing session, section 8). Column order of the row tuples
follows section 4.

## 8. Gold: new columns of `gold_clinical_daily`

Existing 10 columns, key (`participant_id`, `local_date`), staged row set (enrolled ids x
window dates) and values are unchanged. New columns, appended:

| Column | Type | Rule |
|--------|------|------|
| `total_sleep_min` | INTEGER | see below |
| `deep_sleep_pct` | DOUBLE | see below |
| `sleep_efficiency_pct` | DOUBLE | see below |
| `sleep_session_count` | INTEGER | contributing sessions (including exact duplicates), 0 when none |
| `sleep_present` | BOOLEAN | `sleep_session_count > 0` |
| `sleep_quality_flags` | VARCHAR | comma-joined sorted distinct session rule ids of the contributing sessions, or NULL |

Contributing sessions for a participant-day: sessions that are not orphans, whose `date`
parsed and lies in the window, and whose participant and date equal the key. Each
contributing session has the metric tuple (`total_sleep_min`, `deep_sleep_pct`,
`sleep_efficiency_pct`) from `compute_sleep_metrics` over its stages (invalid stage
durations passed as `None`). If the contributing sessions have exactly one distinct tuple
(exact duplicates), that tuple is the day's metrics; with two or more distinct tuples
(a conflict, including a tuple of NULLs versus a full tuple) all three metrics are NULL. No
first/last pick, no averaging. A day without contributing sessions has NULL metrics, count
0, `sleep_present` false and NULL flags.

### Table evolution and MERGE

`gold_clinical_daily` is created with all 16 columns when absent. When it exists without the
sleep columns (a database written by INC-002 or INC-002-01), each missing sleep column is
added with `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` before the MERGE; existing rows keep
their survey values and have NULL sleep columns. The MERGE keeps `ON participant_id AND
local_date`: matched rows update all non-key columns from the staged row (survey columns are
rebuilt from the same inputs, so unchanged inputs reproduce unchanged values), unmatched rows
are inserted, rows no longer staged are retained.

## 9. Operational contract

- Determinism: no time, randomness or machine paths in any table or in the report; a rerun
  on unchanged inputs yields identical tables (compared ordered by all columns) and a
  byte-identical report; output does not depend on `files` mapping order.
- Idempotency: reruns never duplicate a key; changing one sleep session changes exactly that
  day's sleep columns and no other gold cell; changing one survey row does not change sleep
  columns.
- Full rebuild: sleep silver and sleep quality rows reflect only the current inputs.
- Raw immutability: raw files unchanged, nothing created under `data_dir`.
- `run_id` is unchanged: it is derived from the manifest, which already lists sleep files.

## 10. Examples

Session on wake date 2026-01-08 with stages `light 42, deep 81, rem 53, light 90, awake 19`
(contiguous times, `sleep_end` equal to the awake stage start, onset on a whole minute,
supplied `efficiency_pct` 93.3):

| Metric | Value |
|--------|-------|
| `total_sleep_min` | 266 |
| `deep_sleep_pct` | 81 / 266 x 100 = 30.451127819548873 |
| `sleep_efficiency_pct` | 266 / 285 x 100 = 93.33333333333333 |
| rules fired | none |

Examples at `compute_sleep_metrics` level: stage list `awake 30` only: `total_sleep_min` 0,
both percentages NULL. An `awake` stage with duration `None`: `total_sleep_min` kept,
percentages NULL. `[("light", 60), ("deep", 0)]`: 60, 0.0, 100.0. A stage named `nap` with
duration 20: all three NULL.

Examples at session (`build_sleep_layer`) level: a `deep` stage with `duration_min` 0 is
invalid, so the day's three metrics are NULL; a non-awake stage with an unparseable time
gives all NULL; an `awake` stage with an unparseable time keeps `total_sleep_min` and NULLs
the percentages; a non-object stage element gives all NULL.

| Raw timestamp | Local value |
|---------------|-------------|
| `2026-01-07T23:04:11.000` | 2026-01-07 23:04:11 |
| `2026-01-08T04:04:11Z` | 2026-01-07 23:04:11 |
| `2026-01-08T00:04:11+01:00` | 2026-01-07 18:04:11 |
| `2026-01-07 23:04:11` | invalid |

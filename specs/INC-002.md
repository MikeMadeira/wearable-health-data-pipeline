# INC-002: Walking Skeleton

Status: Draft
Source intent: `intents/INC-002-walking-skeleton.md`
Upstream decisions: `reports/INC-001/profiling-findings.md` Section 7 (G1, approved);
G4 ratification of local storage happens at the INC-002 review.

## 1. Public contract

Package `wearable_pipeline` (`src/wearable_pipeline/`):

| Name | Module | Signature |
|------|--------|-----------|
| `RunResult` | `pipeline` | frozen dataclass: `run_id: str`, `database_path: Path`, `report_path: Path` |
| `run_pipeline` | `pipeline` | `run_pipeline(data_dir: Path, output_dir: Path, *, study_start: date = date(2026, 1, 8), study_days: int = 28) -> RunResult` |
| `PipelineError` | `pipeline` | `Exception` subclass raised for I/O and contract failures |
| `main` | `cli` | `main(argv: Sequence[str] \| None = None) -> int` |

CLI: `python -m wearable_pipeline run [--data-dir data] [--output-dir output]`.
`main` returns `0` on success and `1` after printing a message to stderr when
`run_pipeline` raises `PipelineError`. Invalid command-line usage exits through argparse
(code 2). The CLI always uses the default study window.

`run_pipeline` is the only function with behavior. The study window is
`study_days` consecutive dates starting at `study_start` (default 2026-01-08..2026-02-04).

New runtime dependency: `duckdb>=1.4` (embedded SQL engine with transactional MERGE;
added to `pyproject.toml` and `uv.lock` during planning). No other packages.

## 2. Layers and physical layout

- Bronze is the unchanged raw tree under `data_dir` (local analogue of the S3 raw
  prefix). Nothing is copied. The code never writes under `data_dir`.
- Output files: database `output_dir/wearable.duckdb`; report
  `output_dir/quality/report.md`. Directories are created as needed.
- All tables live in the default schema of the DuckDB file.

| Table | Layer | Refresh on each run |
|-------|-------|---------------------|
| `raw_manifest` | bronze | replaced |
| `silver_participants`, `silver_wellness_survey` | silver | replaced |
| `quality_results`, `quality_rejects` | quality | replaced (current run only) |
| `gold_clinical_daily` | gold | MERGE (created if absent, never truncated) |

## 3. Inputs and failure contract

Required inputs under `data_dir`: `participants/participants.csv` and
`health_summaries/wellness_survey.csv`, UTF-8 CSV with a header row.

- Required `participants.csv` columns: `participant_id, device_id, age, height_cm,
  gender, chronotype, max_heart_rate`.
- Required `wellness_survey.csv` columns: `participant_id, date, fatigue_score,
  stress_score, readiness_score, sleep_quality_score`.

`PipelineError` (CLI exit 1) is raised when: `data_dir` is not a directory; a required
file is missing or unreadable; a required column is missing; `study_days < 1`. All
checks happen before any table is touched, so a failed run leaves previously committed
tables unchanged. Field-level data defects never raise.

All derived tables are written in one DuckDB transaction.

## 4. `raw_manifest` (bronze)

Grain: one row per regular file under `data_dir` (recursive), including
`data_dictionary.md`. Key: `relative_path`.

| Column | Type | Rule |
|--------|------|------|
| `relative_path` | VARCHAR | POSIX path relative to `data_dir` |
| `source` | VARCHAR | see mapping below |
| `size_bytes` | BIGINT | file size |
| `sha256` | VARCHAR | lowercase hex SHA-256 of the file bytes |
| `record_count` | BIGINT | CSV: number of data rows (excluding header); all other files: NULL |

Source mapping: `participants/participants.csv` -> `participants`;
`health_summaries/device_metadata.csv` -> `device_metadata`;
`health_summaries/wellness_survey.csv` -> `wellness_survey`;
`wearable_events/<id>/sleep.json` -> `sleep`; `.../steps.json` -> `steps`;
`.../heart_rate.json` -> `heart_rate`; `data_dictionary.md` -> `documentation`; any
other file -> `unclassified`. No hard file count is asserted.

The manifest is recorded only; change detection belongs to INC-006.

## 5. Run identifier

`run_id` = first 16 hex characters of the SHA-256 of the UTF-8 text made of one line
`"{relative_path}\t{sha256}\n"` per manifest row, in ascending `relative_path` order.
It depends only on the input bytes and paths (no time, no randomness, not on
`study_start`/`study_days`).

## 6. Silver

All raw values are kept as read (VARCHAR); normalized columns are added. No row is
dropped and no raw value is changed. `source_row_number` is the 1-based data-row number
in the file (header excluded).

### `silver_participants`

Grain: one row per `participants.csv` data row. Key: `participant_id` (unique when
`is_duplicate_key` is false for all rows).

Columns: `participant_id`, `source_row_number` (INTEGER), `device_id`, `age`,
`height_cm`, `gender`, `chronotype`, `max_heart_rate` (all VARCHAR raw),
`is_duplicate_key` (BOOLEAN), `quality_flags` (VARCHAR).

### `silver_wellness_survey`

Grain: one row per `wellness_survey.csv` data row. Natural key
(`participant_id`, `local_date`), unique when no row has `is_duplicate_key`.

Columns: `participant_id`, `source_row_number` (INTEGER), `date_raw`,
`fatigue_score_raw`, `stress_score_raw`, `readiness_score_raw`,
`sleep_quality_score_raw` (VARCHAR raw), `local_date` (DATE, NULL when `date_raw` is not
an ISO `YYYY-MM-DD` calendar date), `fatigue_score`, `stress_score`, `readiness_score`,
`sleep_quality_score` (INTEGER, NULL when the raw value is invalid), `is_orphan`,
`is_duplicate_key`, `is_out_of_window` (BOOLEAN), `quality_flags` (VARCHAR).

`quality_flags` is the comma-joined, alphabetically sorted rule ids that flagged the row,
or NULL when none.

Date/time semantics: survey dates are calendar dates in the study-local timeline
(UTC-05:00); no time-of-day or offset is involved. The study window is the inclusive
range `study_start .. study_start + study_days - 1`.

## 7. Quality rules

Handling values: `flag` (kept, annotated), `withhold_field` (only the affected field is
unavailable downstream), `exclude_from_output` (kept in silver, excluded from outputs
that require the join or window). Severity values: `high`, `medium`.
For every rule, `checked_count` is the number of source rows evaluated and
`failed_count` is the number of source rows flagged by the rule.

| rule_id | source | Condition (row fails when) | Handling | Severity | Reason (exact text) |
|---------|--------|----------------------------|----------|----------|---------------------|
| `PARTICIPANTS_KEY_DUPLICATE` | `participants` | `participant_id` occurs in more than one row | `flag` | `high` | `participant_id occurs in more than one participants row` |
| `SURVEY_ORPHAN_PARTICIPANT` | `wellness_survey` | `participant_id` is not an enrolled id in `participants.csv` | `exclude_from_output` | `medium` | `participant_id is not enrolled in participants.csv` |
| `SURVEY_DUPLICATE_PARTICIPANT_DAY` | `wellness_survey` | (`participant_id`, `local_date`) occurs in more than one row (rows with NULL `local_date` are not grouped) | `withhold_field` | `high` | `participant_id and date occur in more than one survey row` |
| `SURVEY_SCORE_INVALID` | `wellness_survey` | any score is blank, not an integer string, or outside its inclusive range | `withhold_field` | `medium` | `a score is blank, not an integer, or outside its allowed range` |
| `SURVEY_DATE_OUT_OF_WINDOW` | `wellness_survey` | `local_date` is NULL or outside the study window | `exclude_from_output` | `medium` | `date is not a valid ISO date or is outside the study window` |

Score ranges (data dictionary): `fatigue_score` 1-5, `stress_score` 1-5,
`readiness_score` 0-10, `sleep_quality_score` 1-5. A score is an integer string
(optional surrounding whitespace, no decimals); anything else is invalid.

Enrolled ids are the distinct `participant_id` values in `participants.csv`.

All five rules are always evaluated and always produce one `quality_results` row, with
`failed_count = 0` when nothing fails.

### `quality_results`

Grain: one row per (`run_id`, `rule_id`, `source`). Key: (`run_id`, `rule_id`, `source`).
Columns: `run_id`, `rule_id`, `source`, `handling`, `severity`, `reason` (VARCHAR; the
rule's exact reason text from section 7, constant per rule), `checked_count`,
`failed_count` (BIGINT).

### `quality_rejects`

Grain: one row per (flagged source row, rule). Key: (`run_id`, `rule_id`, `row_ref`).
Columns: `run_id`, `rule_id`, `source`, `row_ref` (VARCHAR `"{relative_path}:{source_row_number}"`),
`reason` (VARCHAR, equal to the rule's reason text from section 7), `raw_values` (VARCHAR, JSON object
mapping every CSV column name to its raw string value for that row, no values altered).

## 8. Gold: `gold_clinical_daily`

Grain: one row per enrolled participant per study-window day. Key
(`participant_id`, `local_date`), enforced as a primary key. Row set staged each run:
distinct enrolled ids x window dates (50 x 28 = 1,400 on the profiled data). Orphan
participants never appear.

| Column | Type | Rule |
|--------|------|------|
| `participant_id` | VARCHAR | key |
| `local_date` | DATE | key |
| `fatigue_score`, `stress_score`, `readiness_score`, `sleep_quality_score` | INTEGER | see aggregation |
| `survey_present` | BOOLEAN | `survey_row_count > 0` |
| `survey_row_count` | INTEGER | contributing survey rows |
| `survey_valid_score_count` | INTEGER | number of the four scores that are non-NULL |
| `survey_quality_flags` | VARCHAR | comma-joined sorted distinct `quality_flags` rule ids of the contributing rows, or NULL |

Contributing rows: survey rows that are not orphans and fall in the window for that
participant-day (including all rows of a duplicate group).

Per-score aggregation over contributing rows: take the distinct non-NULL normalized
values; exactly one distinct value -> that value; none or two or more -> NULL. Exact
duplicates therefore never inflate or change a value; conflicting values withhold only
the conflicting score (no first/last pick, no averaging). Other scores of the same day
remain usable. Missing days are not imputed.

### MERGE semantics

The staged row set is merged into `gold_clinical_daily` with
`MERGE ... ON participant_id AND local_date`: matched rows update all non-key columns;
unmatched rows are inserted. Rows already in gold that the staged set no longer produces
are retained (never silently deleted); their treatment is deferred to INC-006.

## 9. Operational contract

- Determinism: no wall-clock time, random values or machine paths appear in any table or
  in the report. A rerun on unchanged inputs yields identical contents for every table
  (compared ordered by all columns) and a byte-identical report.
- Idempotency: reruns never create duplicate keys in any table; changing one survey
  value changes exactly the affected gold row.
- Full rebuild: manifest, silver and quality tables always reflect the current inputs
  only; only gold accumulates through MERGE.
- Raw immutability: files under `data_dir` are byte-unchanged and no file is created
  there.
- Failure surfacing: `PipelineError` / exit code 1 with a stderr message naming the
  problem; data defects are reported only through quality tables and the report.

### Report `quality/report.md`

UTF-8, LF line endings, ending with one newline. Contains the run id
(`Run id: <run_id>`), the number of manifest files (`Manifest files: <n>`), and a Markdown table with the header
`| rule_id | source | handling | severity | checked | failed |` followed by one row per
`quality_results` row ordered by `rule_id`, `source`, formatted as
`| <rule_id> | <source> | <handling> | <severity> | <checked> | <failed> |`.

## 11. Verification gates

1. `python -m pytest -q`: planning baseline fails with `NotImplementedError` from the
   `run_pipeline` / `main` stubs; implementation turns it green without test edits.
2. `uv lock --check` consistent; container gate (Docker build and in-container pytest)
   passes with `duckdb` installed from the project metadata.
3. Changes confined to `src/`, `tests/`, `specs/`, `pyproject.toml`, `uv.lock` and
   `reports/INC-002/`.
4. Human real-data evidence recorded in `implementation.md`: one command run; 1,400 gold
   rows; 1,414 survey rows in silver with 14 `P999` orphans; `SURVEY_ORPHAN_PARTICIPANT`
   failed_count 14; second run produces identical tables and report; `data/` SHA-256
   unchanged. G4 (native DuckDB tables with MERGE) ratified at this review.

## 12. Out of scope

Sleep, steps and heart-rate silver or gold columns; device-metadata silver or gold;
`gold_participant_devices`; weekly and cohort outputs; incremental mode and file-change
detection; Docker or container changes; README, diagram and query output; cloud
deployment; notebooks; participant attribute validation beyond key uniqueness.

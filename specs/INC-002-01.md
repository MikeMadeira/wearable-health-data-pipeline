# INC-002-01: Silver Normalization

Status: Draft
Source intent: `intents/INC-002-01-silver-normalization.md`
Amends: `specs/INC-002.md` sections 6, 7, 10 and 12. Everything not named here is
unchanged (public API, CLI, `raw_manifest`, run id, gold, MERGE, report layout).

## 1. Public contract

New module `wearable_pipeline.normalize` (pure functions, no I/O):

| Name | Signature |
|------|-----------|
| `parse_integer` | `parse_integer(raw: str) -> int \| None` |
| `parse_iso_date` | `parse_iso_date(raw: str) -> date \| None` |

`run_pipeline`, `RunResult`, `PipelineError` and `main` keep their signatures. The
pipeline must obtain every typed value through these two functions so the unit tests
and the silver tables share one definition.

## 2. Normalization rules

- `parse_integer`: trim surrounding whitespace (as `str.strip()`), then accept only an
  optional `+`/`-` sign followed by one or more ASCII digits. The result must fit a
  signed 32-bit integer (DuckDB `INTEGER`); anything else, including blank, decimals
  (`"38.0"`), thousands separators, non-ASCII digits and overflow, returns `None`.
- `parse_iso_date`: trim surrounding whitespace, then accept only `YYYY-MM-DD` made of
  ASCII digits that is a real calendar date. Compact (`20260108`), ISO week, slash,
  time-bearing or any other layout returns `None`. No repair other than trimming.
- Survey scores keep their rule: `parse_integer` then the inclusive range check.
  A score is invalid when `parse_integer` is `None` or outside its range.

## 3. Silver schema changes

### `silver_participants`

Grain and key unchanged: one row per `participants.csv` data row. Columns:
`participant_id`, `device_id`, `age` (INTEGER), `height_cm` (INTEGER), `gender`,
`chronotype`, `max_heart_rate` (INTEGER), `is_duplicate_key` (BOOLEAN),
`quality_flags` (VARCHAR). `source_row_number` is removed. `age`, `height_cm` and
`max_heart_rate` are `parse_integer` of the raw value; `None` becomes NULL for that
field only and the row stays. The raw text of these fields is not stored in silver.

### `silver_wellness_survey`

Grain unchanged: one row per `wellness_survey.csv` data row. Columns: `participant_id`,
`local_date` (DATE, NULL when `parse_iso_date` fails), `fatigue_score`, `stress_score`,
`readiness_score`, `sleep_quality_score` (INTEGER, NULL when invalid), `is_orphan`,
`is_duplicate_key`, `is_out_of_window` (BOOLEAN), `quality_flags` (VARCHAR).
Removed: `source_row_number`, `date_raw`, and the four `*_score_raw` columns.
`is_out_of_window` is true only when `local_date` is a valid date outside the study
window; it is false when `local_date` is NULL. An unparseable date is identified by
`local_date IS NULL` and the `SURVEY_DATE_UNPARSEABLE` flag.

No row is dropped. Rows are identified by natural key; the original text of any flagged
row is in `quality_rejects` (`row_ref` and `raw_values` unchanged, still carrying the
1-based source row number in `row_ref`). Silver tables are compared ordered by all
columns, so determinism does not depend on row order.

## 4. Quality rules

Rules are evaluated every run and always produce one `quality_results` row (zero counts
when nothing fails). `checked_count` is the number of source rows of that source for
every rule. Seven rules in total; the three below are new or changed:

| rule_id | source | Row fails when | Handling | Severity | Reason (exact text) |
|---------|--------|----------------|----------|----------|---------------------|
| `PARTICIPANTS_INTEGER_INVALID` | `participants` | `age`, `height_cm` or `max_heart_rate` is not accepted by `parse_integer` | `withhold_field` | `medium` | `age, height_cm or max_heart_rate is not an integer` |
| `SURVEY_DATE_UNPARSEABLE` | `wellness_survey` | `parse_iso_date(date)` is `None` | `exclude_from_output` | `medium` | `date is not a valid YYYY-MM-DD calendar date` |
| `SURVEY_DATE_OUT_OF_WINDOW` | `wellness_survey` | date parses but lies outside the study window | `exclude_from_output` | `medium` | `date is outside the study window` |

`SURVEY_DATE_OUT_OF_WINDOW` keeps its id; its reason text changes and it no longer
fires for unparseable dates, so the two rules never flag the same row. The other four
rules and their reasons are unchanged. A row counts once per rule even when several
fields fail. Flagged rows get one `quality_rejects` row per rule (reason equal to the
rule's reason text) and their rule ids appear in `quality_flags`. A participant row
failing `PARTICIPANTS_INTEGER_INVALID` still counts as a normal row for enrolment and for
the survey orphan check.

## 5. Gold and other layers

Unchanged. `gold_clinical_daily` has the same key, columns, values and MERGE behavior
for the same inputs; an unparseable or out-of-window survey row contributes nothing to
gold, and a whitespace-padded valid date contributes to the trimmed day.

## 7. Verification gates

1. `python -m pytest -q`. Planning baseline: unit tests of `normalize` fail with
   `NotImplementedError` from the stubs; the pipeline-level tests fail on their
   assertions because the pre-amendment pipeline still has the old schema and rules.
   Implementation turns all green; INC-002 tests are edited only where they asserted
   removed columns, the old rule list or the old reason text.
2. Changes confined to `src/`, `tests/`, `specs/` and `reports/INC-002-01/`; no
   dependency changes. `notebooks/INC-002-review.ipynb` is updated by the human after
   implementation.
3. Human real-data evidence recorded in `implementation.md` as listed in the intent:
   1,400 gold rows, 1,414 silver survey rows with 14 `P999` orphans, new rules at zero
   failures, gold identical to the INC-002 run, rerun identical, `data/` unchanged.

## 8. Out of scope

As in the intent: incremental or persistent manifest, lineage columns, other date
layouts, sleep/steps/heart-rate silver, device metadata, weekly and cohort outputs,
participant domain validation beyond integer conversion.
